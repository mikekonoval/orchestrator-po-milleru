## Что ещё прочитать для этого шага

6. **`missing_phase{N}.md`** — секцию `## FOUND`.

## Что сделать

По каждому пункту из `## FOUND` докажи: **это реальная проблема В НАШЕМ проекте или теоретический риск?**

Учитывай:
- **Аудитория** из `idea/03-audience/` — кто реально пользователь, что он реально будет делать.
- **MVP scope** из `idea/09-mvp/` — что внутри, что отложено. Если упущение — это feature вне MVP, оно НЕ реальное на этом этапе.
- **Failure modes** из `idea/11-risks/` — это явный список того, чего боимся. Совпадение с failure mode → реальное.
- **Объёмы** — десятки на старте, не миллионы.
- **Приоритет: запустить → продать → масштабировать.** Сначала запустим, потом будем красивыми.

«Теоретически может, но не критично для текущего этапа» — это паранойя. Вычёркивай. Не жалей.

## Куда записать

Дополни `missing_phase{N}.md`:

```markdown
## PROVEN
1. <пункт из FOUND>: РЕАЛЬНОЕ — <почему важно ИМЕННО сейчас, на нашем масштабе; ссылка на конкретный JTBD/failure mode если применимо>
2. <пункт из FOUND>: ПАРАНОЙЯ — <почему не критично>
3. ...
```

Используй слово `РЕАЛЬНОЕ` / `РЕАЛЬНЫЕ` или `ПАРАНОЙЯ` явно — парсер оркестратора ищет корень `реальн`.

В финальном ответе: `STATUS=done FILE=missing_phase{N}.md REAL=<число> PARANOIA=<число>`.
